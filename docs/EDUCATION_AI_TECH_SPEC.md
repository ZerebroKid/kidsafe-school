## 2) The Four-App System

```mermaid
flowchart LR
  AdminWeb["Zerebro Admin"]
  CampusWeb["Zerebro Campus"]
  ZConnect["ZConnect (parent + teacher)"]
  ZKid["ZKid (student)"]
  Functions["Cloud Functions"]

  AdminWeb --> Firestore[(Firestore)]
  CampusWeb --> Firestore
  ZConnect --> Firestore
  ZKid --> Firestore
  Functions --> Firestore
  ZConnect --> Functions
  ZKid --> Functions
  CampusWeb --> Functions
```

| Product | Platform | Users | Primary Job |
|---|---|---|---|
| Zerebro Admin | Next.js | Internal team | Create schools, moderate rewards, manage syllabus sources |
| Zerebro Campus | Next.js | School principals | Generate teacher codes, approve teachers, view coverage |
| ZConnect | React Native (Android) | Parents + teachers | Parent: monitor + control child. Teacher: assign topics, view class report |
| ZKid | React Native (Android) | Students | Onboarding + enforcement + study mission + quiz + reward |

Why this split:

- **ZKid isolated** — parent UI is not even bundled, student can't snoop or reverse-engineer.
- **ZConnect combined** — many teachers are also parents; one install for both roles.
- **Zerebro Campus + Admin on web** — table-heavy, filter-heavy UIs are simpler on the web.

## 3) Roles & Multi-Role Users

`users/{userId}` stores a `roles` array, not a single role:

```json
{
  "uid": "user_abc",
  "phone": "+91XXXXXXXXXX",
  "displayName": "Naushad",
  "roles": ["parent", "teacher"],
  "primaryRole": "parent",
  "schoolIds": ["school_001"],
  "teacherProfileIds": ["teacher_123"],
  "createdAt": 1779050000000
}
```

Allowed role strings:

```text
admin | principal | teacher | parent | child
```

On app open, **ZConnect** uses `roles`:

- 1 role → straight into that home screen.
- 2+ roles → show a **role switcher** at the top of the home screen, default to `primaryRole` (or last-used).

```text
+----------------------------+
| [ Parent ]  [ Teacher ]    |  <- role switcher
|----------------------------|
| selected role's home view  |
+----------------------------+
```

Important rules:

- A `child` role is **only** valid in **ZKid**. ZConnect refuses to load student UI even if `roles` includes `child` (defense-in-depth).
- A user can be promoted to `teacher` only via principal approval (teacher code flow, see §6).

## 4) Monorepo Layout

### 4.1 Tooling Stack

- **pnpm workspaces** — fast installs, hoisted node_modules, RN-friendly.
- **Turborepo** — cached, parallel builds across packages.
- **TypeScript project references** — type-safe shared packages.
- **Firebase Emulator Suite** — local Firestore + Functions for dev.
- **Tailwind CSS** — all UI styling (no custom `shared-ui-*` component packages):
  - **Web** (`admin-web`, `principal-web`): Tailwind CSS via Next.js
  - **Mobile** (`guardian`, `kids`): [NativeWind](https://www.nativewind.dev/) (Tailwind for React Native)

> ESLint, Prettier, Husky, and lint-staged are **deferred to a later phase** — not in the initial monorepo bootstrap.

### 4.3 Key Config Files

**`pnpm-workspace.yaml`**

```yaml
packages:
  - "apps/*"
  - "packages/*"
```

**`.npmrc`** (root)

```text
node-linker=hoisted
shamefully-hoist=true
public-hoist-pattern[]=*
```

`hoisted` linker is required so React Native's Metro can resolve hoisted native dependencies.

**`turbo.json`**

```json
{
  "pipeline": {
    "build":     { "dependsOn": ["^build"], "outputs": ["dist/**", "build/**", ".next/**"] },
    "typecheck": { "dependsOn": ["^build"], "outputs": [] },
    "test":      { "dependsOn": ["^build"], "outputs": ["coverage/**"] }
  }
}
```

**`apps/guardian/metro.config.js`** (and same shape for `apps/kids`)

```javascript
const path = require('path');
const { getDefaultConfig } = require('@react-native/metro-config');

const workspaceRoot = path.resolve(__dirname, '../..');
const projectRoot = __dirname;

const config = getDefaultConfig(projectRoot);

config.watchFolders = [workspaceRoot];
config.resolver.nodeModulesPaths = [
  path.resolve(projectRoot, 'node_modules'),
  path.resolve(workspaceRoot, 'node_modules'),
];
config.resolver.disableHierarchicalLookup = true;

module.exports = config;
```

This combo is the standard fix for the Metro + workspace symlink issue.

### 4.4 Native Module Ownership

| Native module | ZConnect | ZKid |
|---|---|---|
| AppBlocker accessibility | no | yes |
| ScreenTime / UsageStats | no | yes |
| Foreground service | minimal (FCM only) | yes (location + enforcement) |
| Location writer | no | yes |
| DeviceAdmin | no | yes |
| Pin | no | yes |
| Firebase Messaging | yes | yes |
| Maps | yes | no |

The ZKid APK keeps all the heavy native modules; ZConnect stays lean. This is a meaningful UX win — parents don't get scared by long permission lists.

## 5) Web Apps In The Monorepo

**Zerebro Campus** and **Zerebro Admin** are Next.js 14 (App Router) web apps:

- **server actions + route handlers** for callable-style server logic
- **`shared-firebase`** package for both client SDK and admin SDK use
- **Tailwind CSS** for all web UI (utility classes in each app — no separate shared UI package)
- Hosted on **Firebase Hosting** or **Vercel** (decision pending; Vercel recommended for App Router maturity)

`apps/principal-web/` (Zerebro Campus) route map:

```text
/                            -> login (phone OTP)
/onboarding                  -> claim school via invite code
/dashboard                   -> coverage by class
/dashboard/classes/:classId  -> per-class detail
/teachers                    -> approve/reject teacher requests
/teachers/code               -> rotate teacher code
/syllabus                    -> review fetched topics for whole school
```

`apps/admin-web/` (Zerebro Admin) route map:

```text
/                            -> SSO/email + OTP gated
/schools                     -> CRUD schools, principals
/syllabus-sources            -> manage online adapters (NCERT, CBSE etc.)
/rewards                     -> moderate rewardCatalog
/users                       -> impersonate, ban
/audit                       -> action log
```

## 7) Payment & Subscriptions (Deferred)

Payment and subscription plumbing is **not in the current build scope**. Build the full product end-to-end first (schools, teachers, child study loop, curated lessons, quizzes, reports), then add monetization.

When implemented later, the planned approach (for reference only):

- **Provider:** Razorpay (India — UPI, cards, school B2B + parent B2C recurring)
- **Plans:** `school_basic`, `school_premium`, `parent_premium`
- **Server-only writes:** `subscriptions/`, `paymentEvents/`, `invoices/` — only Cloud Functions mutate
- **Gating:** education features read-only when subscription lapses; KidSafe core stays free

Do **not** add `packages/shared-payments/`, Razorpay SDK, billing routes, or webhook handlers until a dedicated post-MVP payment phase.

### 8.3 Curated Topic Content (No AI Generation)

**Source of truth:** content team prepares JSON offline. Engineering **imports** it — no OpenAI/Gemini for lessons in MVP.

Firestore path:

```text
curriculum/{curriculumId}/chapters/{chapterId}/topics/{topicId}
```

Example: `curriculum/cbse_8_science/chapters/force_pressure/topics/types_of_forces`

Example doc (Class 8 Science):

```json
{
  "curriculumId": "cbse_8_science",
  "grade": 8,
  "subject": "science",
  "chapterNo": 11,
  "chapterName": "Force and Pressure",
  "topicId": "types_of_forces",
  "topicName": "Types of Forces",
  "explanation": "Force is a push or pull that can change the speed, direction, or shape of an object.",
  "examples": [
    "Pushing a door open",
    "Magnet pulling an iron nail"
  ],
  "videoUrl": "https://youtube.com/watch?v=approved_intro",
  "brainstorming": [
    {
      "question": "How does a solid turn into a liquid?",
      "answer": "When heat is added, particles move faster and break free from fixed positions — this is melting.",
      "videoUrl": "https://youtube.com/watch?v=approved_brainstorm"
    }
  ],
  "quiz": [
    {
      "questionId": "q1",
      "type": "mcq",
      "question": "Force is a:",
      "options": ["color", "push or pull", "sound", "temperature"],
      "correctIndex": 1,
      "explanation": "Force means push or pull."
    }
  ],
  "status": "published",
  "curatedBy": "content_team",
  "publishedAt": 1779050000000
}
```

Field guide:

| Field | Purpose |
|---|---|
| `explanation` | Main lesson text child reads first |
| `examples` | Real-life examples (array of strings) |
| `videoUrl` | Intro/explanation YouTube link (approved) |
| `brainstorming[]` | Common gaps students miss — each has question, answer, videoUrl |
| `quiz[]` | MCQs bundled with topic; server scores against this |
| `status` | `draft` → `published` (only published topics assignable) |

Import pipeline:

```text
content-team/*.json  →  scripts/import-curriculum.ts  →  Firestore curriculum/*
```

Classes/subjects link to a curriculum:

```json
{
  "name": "Science",
  "curriculumId": "cbse_8_science"
}
```

ZKid reads topic doc directly when child opens an assignment — **no `aiLessonGenerator` callable**.

## 8.4 Feature Interaction Map

This section answers: **"when X happens, what else fires?"**

Use it together with the function inventory (§9) to understand any code path end-to-end.

### 8.4.1 Setup chain (one-time per school)

```mermaid
sequenceDiagram
  participant Admin as Zerebro Admin
  participant Principal as Zerebro Campus
  participant Teacher as ZConnect (teacher mode)
  participant Parent as ZConnect (parent mode)
  participant Child as ZKid
  participant FN as Cloud Functions
  participant FS as Firestore

  Admin->>FS: create schools/{schoolId}
  Admin-->>Principal: share invite code
  Principal->>FN: claimSchool(inviteCode)
  FN->>FS: schools/{id}.principalUid = caller
  Principal->>FS: create classes/{classId} + subjects (with curriculumId)
  Principal->>FN: rotateTeacherCode()
  FN->>FS: schools/{id}.teacherCode = NEW
  Principal-->>Teacher: share teacher code
  Teacher->>FN: requestTeacherJoin(code, displayName)
  FN->>FS: teachers/{teacherId}.status = "pending"
  Principal->>FN: approveTeacher(teacherId)
  FN->>FS: teachers/{teacherId}.status = "active"
  FN->>FS: users/{teacherUid}.roles += "teacher"
  Parent->>FS: pair child (existing v1 flow)
  Child->>FN: joinSchool(schoolCode, grade, section)
  FN->>FS: children/{uid}.classId = ...
  FN->>FS: classes/{classId}.studentChildUids += childUid
```

**Side effects:**
- `users/{teacherUid}.roles += "teacher"` → ZConnect role switcher reflects new role on next snapshot
- `classes/{classId}.studentChildUids[]` → principal class roster updates
- `children/{uid}.classId` → ZKid Study Mission listener starts filtering by this classId

### 8.4.2 Daily learning loop

```mermaid
sequenceDiagram
  participant Teacher as ZConnect (teacher)
  participant FN as Cloud Functions
  participant FS as Firestore
  participant Child as ZKid
  participant Parent as ZConnect (parent)

  Teacher->>FN: assignTopic(classId, subjectId, chapterId, topicId)
  FN->>FS: studyAssignments/{id} created
  Note over FS: Snapshot fires
  FS-->>Child: ZKid Study Mission shows new card
  FS-->>Teacher: Teacher home updates assignments list

  Child->>FS: read curriculum/.../topics/{topicId}
  Note over Child: renders explanation + examples + video + brainstorming + quiz

  Child->>FN: submitQuizAttempt(assignmentId, answers)
  FN->>FS: read topic.quiz to validate
  FN->>FS: quizAttempts/{id} written with server score
  Note over FS: Trigger fires
  FS->>FN: onQuizAttemptWrite (trigger)
  FN->>FS: pick eligible rewardCatalog entry
  FN->>FS: rewardUnlocks/{id} written

  FS-->>Child: ZKid reward screen
  FS-->>Parent: Parent Study tab shows score + reward
  FS-->>Teacher: Teacher class report updates
```

**Side effects:**
- Creating one `studyAssignments` doc updates 2 UIs (ZKid + teacher).
- Creating one `quizAttempts` doc triggers reward creation AND updates 3 UIs (ZKid, parent, teacher).
- All updates are real-time via Firestore snapshots — no polling.

### 8.4.3 Nightly aggregation (principal dashboards)

```mermaid
sequenceDiagram
  participant Cron as Cloud Scheduler
  participant FN as aggregateClassReports
  participant FS as Firestore
  participant Principal as Zerebro Campus

  Cron->>FN: trigger at 02:00 IST
  FN->>FS: query quizAttempts (last 24h, group by classId)
  FN->>FS: classReports/{classId}/daily/{date} written
  FN->>FS: mark topics weak if class avg < 60%
  Principal->>FS: dashboard reads pre-computed classReports
  FS-->>Principal: fast load (< 1s)
```

**Why pre-compute?** Live aggregation of thousands of `quizAttempts` on every dashboard load would be slow and expensive. Cron writes summaries once a night → dashboards read tiny `classReports` docs.

### 8.4.4 Cross-feature interaction matrix

What writing to one collection affects elsewhere:

| Write | Triggers / Affects |
|---|---|
| `studyAssignments/{id}` (create) | ZKid Study Mission (snapshot); teacher home list (snapshot) |
| `quizAttempts/{id}` (create) | `onQuizAttemptWrite` trigger → `rewardUnlocks/{id}`; parent Study tab; teacher class report; nightly `aggregateClassReports` |
| `rewardUnlocks/{id}` (create) | ZKid reward screen; parent Study tab (reward chip) |
| `users/{uid}.roles += 'teacher'` | ZConnect role switcher appears on next render |
| `children/{uid}.classId` set | ZKid Study Mission listener registers correct class filter; class roster updates for teacher + principal |
| `schools/{id}.teacherCode` rotated | Old code becomes invalid for `requestTeacherJoin` |
| `curriculum/.../topics/{id}` written by import | Becomes assignable in teacher's "Assign Topic" picker (status filter: `published`) |
| `rewardCatalog/{id}` created | Eligible for `onQuizAttemptWrite` reward picker on next quiz pass |

### 8.4.5 What does NOT trigger anything

For clarity:

| Write | No side effect |
|---|---|
| `children/{uid}.currentLocation` | Parent map updates, but no education feature reads this |
| `apps/{pkg}.isBlocked` | KidSafe enforcement only; not part of education chain |
| `usageDaily/*` | Parent screen-time UI only |
| Pure principal CRUD on `classes/*` (renaming etc.) | Subscribed UIs update; no callable/trigger fires |

This separation keeps the education stack independent of the KidSafe-core stack — either can break without taking down the other.

```text
apps/functions/src/crons/oneTimeMigration_v1_to_v2.ts
```

For every existing `users/*` doc:

```ts
const doc = await db.doc(`users/${uid}`).get();
const role = doc.data().role; // old single string
await doc.ref.update({
  roles: [role],
  primaryRole: role,
});
```

Run once after deploy. Idempotent — checks if `roles` already exists.

## 13) Risks & Safeguards

| Risk | Mitigation |
|---|---|
| Metro + monorepo path issues | Standard `watchFolders` + `nodeModulesPaths` + `disableHierarchicalLookup` config; `node-linker=hoisted` |
| Native module path break after extraction | Keep Gradle module names identical to v1, just relocate the source root |
| Wrong curated quiz answer | Content team QA + import validator + spot-check before `published` status |
| Unsafe reward link | Strict allowlist in `rewardCatalog`, admin moderation only |
| Multi-role user confusion | Single role switcher UI, `primaryRole` default, audit logging on switch |
| Cross-app data leak | Firestore rules strictly check role + school binding; ZKid refuses parent-shaped reads |
| Child app reverse-engineered | ZKid APK doesn't bundle parent UI; secrets are server-side only |
